# Сквозные LLM-тесты

50 последовательных тестов публичного API: настоящий LLM, очередь заданий и сохранение
данных. Нужен запущенный gateway с auth, core, assistant-worker и поиском. Голосовой
интерфейс не проверяется. Backend не импортируется; ответы сервисов не подменяются.

## Установка и запуск

Python 3.12 или новее:

```bash
python -m venv /tmp/voice-assistant-local-tests
source /tmp/voice-assistant-local-tests/bin/activate
python -m pip install -r "local tests/requirements.txt"
python -m pytest "local tests" --base-url http://127.0.0.1:8080 -v
```

Запускать из корня репозитория. Адрес обязателен, это адрес публичного gateway,
а не внутреннего worker. Допустимы HTTPS и IP с портом без схемы:

```bash
python -m pytest "local tests" --base-url 192.168.1.20:8080 --job-timeout 240 -v
python -m pytest "local tests" --base-url https://assistant.example.com -v
python -m pytest "local tests" --base-url localhost:8080 --collect-only -q
python -m pytest "local tests" --base-url localhost:8080 -k test_14 -v
python -m pytest "local tests/test_meeting_scenarios.py" --base-url localhost:8080 -v
```

Для согласованного тестового сервера с самоподписанным сертификатом:

```bash
python -m pytest "local tests" --base-url https://194.169.160.248:31016 --insecure -v
```

`--insecure` отключает проверку TLS только у клиента этого запуска. По умолчанию
проверка включена; глобальное хранилище доверия и настройки сервера не меняются.

Для HTTP сервер должен выдавать session cookie без `Secure` (`COOKIE_SECURE=false` в
локальном окружении). Клиент не обходит политику cookie.
Не указывайте `-n`: параллельный запуск запрещён. Тайм-аут по умолчанию — 180 секунд
на ожидание каждого задания; отдельный HTTP-запрос ограничен 30 секундами.

## Сценарии

После каждого запуска автоматически создаётся `local tests/reports/latest.html`.
Откройте его в браузере: сводка статусов, длительность, поиск, фильтры и раскрывающиеся
диалоги с ассистентом и ошибки. Отчёт автономный, не обращается к внешним ресурсам.
Ошибки подготовки и очистки отмечаются отдельно от падения сценария; незавершённые
тесты не считаются прошедшими. Пароли и известные session cookie маскируются.

Путь можно изменить:

```bash
python -m pytest "local tests" --base-url localhost:8080 --report-path /tmp/llm-report.html -v
```

По умолчанию предыдущий отчёт перезаписывается. `--collect-only` отчёт не создаёт
и не перезаписывает. Папка `reports` исключена из Git. В отчёте есть тестовые диалоги
и данные записей; учитывайте это при передаче файла другим людям.

Офлайн-проверка генератора отчёта (не вызывает API и не входит в 50 сценариев):


Ответы проверяются по полям записей и карточкам, без точного сравнения фраз LLM.
Создание проверяется повторным GET; запросы списков и поиска не должны менять записи.
Смысловой поиск проверяется строго: нет нужной карточки — тест падает.
Редактирование сверяет все поля записи: изменяться должны только запрошенные значения.
Для отдельного повторения проверяются его исходный `occurrence_at`, неизменность базовой
серии и всех соседних повторений. Для изменения всей серии проверяются все развёрнутые
повторения, сохранение идентификатора и рост версии. Подготовка данных выполняется через
API записей; проверяемое действие всегда проходит через LLM в чате.
Относительные даты считаются в `Europe/Moscow`; для «через два часа» допускается
минутная точность и интервал времени отправки запроса. Часы машины запуска и сервера
должны быть синхронизированы.

## Изоляция, очистка и диагностика

Каждый тест регистрирует отдельного пользователя со случайными учётными данными.
Набор предназначен для тестового окружения: создаёт данные и расходует токены
настроенного на сервере LLM. Глобальные настройки провайдера не меняются.

После теста записи удаляются по актуальным версиям, только внутри его аккаунта.
При незавершённом задании сначала очищается тестовый чат, чтобы отменить задание.
Ошибки очистки выводятся отдельной ошибкой teardown. После аварийного завершения
процесса автоматическая очистка не гарантируется.
Аккаунты с префиксом `llmtest_` остаются: API удаления пользователей отсутствует.

Недоступность API, ошибка LLM, отмена или тайм-аут задания — ошибки теста, не skip.
Повторных запусков сценария для получения удачного ответа нет. При падении pytest
показывает отправленные реплики, время отправки, job_id, статус, результат и ошибку
задания; assertions содержат фактические и ожидаемые данные. Пароли и cookie не
пишутся в этот отчёт. Для машиночитаемого отчёта можно добавить
`--junitxml=/tmp/llm-tests.xml`.
