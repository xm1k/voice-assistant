# Голосовой ассистент «Голосок»

Прототип личного ассистента, который понимает запросы на естественном языке (текстом или голосом), управляет задачами, напоминаниями и встречами, ищет старые записи и синхронизируется с Яндекс Календарём.

## Основные сценарии

Ассистент работает с тремя типами сущностей. Ниже — какие действия доступны для каждого из них.

| Действие | Встреча | Напоминание | Задача |
|---|:---:|:---:|:---:|
| Создавать | ✅ | ✅ | ✅ |
| Завершать | ❌ | ✅ | ✅ |
| Удалять | ✅ | ✅ | ✅ |
| Переносить | ✅ | ✅ | ❌ |
| Редактировать | ✅ | ✅ | ✅ |

| Повторяющаяся | ✅ | ✅ | ❌ |

## Демонстрация

### Путь запроса

![](docs/assets/request-flow.gif)

Пользователь отправляет текст или голос. Голос сначала распознаётся в текст, затем идёт по тому же пути, что и обычное сообщение. Core сохраняет сообщение, задание и outbox одной транзакцией, assistant-worker получает задание через RabbitMQ, вызывает LLM и при необходимости RAG, после чего core проверяет и атомарно применяет решение.

### Три ветки решения модели

![Три ветки решения LLM: clarify, query, ready](docs/assets/llm-scenarios.gif)

- `clarify` — не хватает данных, ассистент задаёт уточняющий вопрос и сохраняет контекст.
- `query` — нужны данные, ассистент запрашивает их через RAG/core и возвращает результат модели.
- `ready` — можно ответить или выполнить действие: обычный ответ либо проверенный пакет команд.

## Как это работает

Ключевой принцип: **LLM предлагает решение, но не меняет данные напрямую**. Модель возвращает структурированный `Decision`, а core проверяет бизнес-правила, права пользователя, версии записей и только затем сохраняет изменения в PostgreSQL.
