## Как обрабатывается запрос

```mermaid
flowchart TD
    U1["Пользователь отправляет<br/>сообщение"]
    B["Бэкенд принимает<br/>и сохраняет запрос"]
    C["Контекст дообогащается"]
    API["Запрос отправляется<br/>в LLM через API"]
    L{"LLM выбирает сценарий"}

    READY["Готов ответ или действие"]
    CLARIFY["Нужно задать<br/>уточняющий вопрос"]
    QUERY["Нужно получить данные"]
    RAG["Бэкенд находит данные<br/>через RAG"]

    SAVE["Бэкенд проверяет<br/>и сохраняет результат"]
    U2["Пользователь получает ответ"]

    U1 --> B
    B --> C
    C --> API
    API --> L

    L -->|ready| READY
    L -->|clarify| CLARIFY
    L -->|query| QUERY

    QUERY --> RAG
    RAG -->|данные передаются в LLM| L

    READY --> SAVE
    CLARIFY --> SAVE
    SAVE --> U2
```

## Подробные схемы сценариев

| Сценарий | Что происходит | Схема |
|---|---|---|
| `ready` | Модель подготовила ответ или действие | [Открыть](ready.md) |
| `clarify` | Для продолжения не хватает данных пользователя | [Открыть](clarify.md) |
| `query` | Модели нужны сохранённые задачи, встречи или напоминания | [Открыть](query.md) |

> LLM не изменяет данные напрямую. Она возвращает структурированное решение, а бэкенд проверяет его и только после этого сохраняет результат.
