# Уточнение пересечений встреч

Модель предлагает команды создания и изменения. Core предварительно применяет весь
набор в savepoint, проверяет итоговое расписание и откатывает предварительные эффекты.
Проверка общая для предварительного и окончательного применения в `apply_decision`.
Запросы расписания ради проверки пересечений от модели не требуются.

Если есть пересечение, `/validate` возвращает `valid=false`, `code=meeting_conflict`,
нормализованные команды и пары конфликтующих интервалов. Предложение сохраняется в
JSON задания. Worker передаёт данные модели, которая возвращает `clarify` без команд.
До завершения этого задания core разрешает только уточнение.

При сохранении вопроса core переносит предложение в `Chat.pending.meeting_conflict`
и создаёт случайный одноразовый token. После явного согласия пользователя модель
повторяет исходные команды и возвращает token в `Decision.conflict_confirmation`.
Core сверяет token, весь набор команд и актуальные конфликты. Согласие применимо
только к сообщению, отправленному после вопроса. После успешного действия pending
очищается. При выборе другого времени модель предлагает новые команды без token.
Понимание естественного ответа пользователя остаётся ответственностью модели.

Созданные в предварительном применении идентификаторы заменяются в предложении
стабильными ссылками на индекс команды: новые UUID не меняют привязку согласия.
Проверка выполняется после всего набора, поэтому учитывает создаваемые вместе встречи
и разрешение пересечения удалением или переносом другой встречи в том же наборе.
Изменение названия и заметок не требует согласия на существующее пересечение.

Окончательное применение повторяет проверку под блокировкой чата пользователя.
Если после preview появился новый конфликт, весь набор откатывается, задание
возвращается в очередь с данными конфликта, модель формулирует вопрос. Outbox и события
записей откатываются вместе с записями.

Конечные серии проверяются по всем повторениям с учётом исключений. Бессрочная серия
проверяется в интервалах остальных конечных встреч без произвольного горизонта.
Для двух бессрочных серий требуется ограничить новую серию датой окончания или числом
повторений. Такое же уточнение нужно, если длительность бессрочной встречи не позволяет
гарантировать отсутствие пересечений её повторений. Core возвращает структурированный
ответ `requires_recurrence_bound=true`, чтобы модель запросила ограничение.
Существующий предел разворачивания серии в 10000 повторений сохраняется.
Прямое редактирование через API записей сохраняет прежнюю семантику предупреждений;
описанное подтверждение относится к командам ассистента.

Локальные проверки без сети:

```sh
python -m pytest shared/tests_v2 -q
```

Сквозные сценарии 51–52 требуют развёрнутого API и настоящего LLM:

```sh
python -m pytest "local tests/test_meeting_scenarios.py" --base-url http://localhost:8080 -k 'test_51 or test_52' -v
```
